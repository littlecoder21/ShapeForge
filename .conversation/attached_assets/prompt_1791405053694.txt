Build a production-quality web application called ShapeForge — an advanced visual shape generator for frontend developers and web designers.

The purpose of this application is NOT to be a general-purpose drawing/illustration app like Figma or Illustrator.

It is a focused Web Shape Generator where developers can visually create sophisticated shapes, curves, waves, blobs, section dividers, polygons, and SVG paths, then convert the same shape into different web-ready formats such as:

- SVG
- SVG "<path>"
- CSS "clip-path: path()"
- CSS "clip-path: polygon()"
- CSS "clip-path: inset()"
- CSS "clip-path: circle()"
- CSS "clip-path: ellipse()"
- CSS "shape()" where appropriate
- HTML + CSS
- React JSX
- JSON shape data

The application should feel like a premium developer tool: clean, technical, fast, precise, visually sophisticated, and highly interactive.

---

TECHNICAL STACK

Use:

- React
- TypeScript
- Vite
- SVG as the primary visual editing/rendering system
- CSS for styling
- Zustand or an equivalent lightweight state-management solution
- Custom TypeScript geometry/path utilities
- No backend for the initial version
- Everything should work client-side

Do NOT make Canvas the primary editor.

Use SVG as the editable geometry surface because the application needs interactive Bézier nodes, handles, paths, curves, and transformations.

Canvas may be used for optional previews or performance-heavy rendering, but the actual vector editing model should be SVG-based.

Do not depend on a huge vector-design framework unless absolutely necessary.

Build the application's own normalized vector/path data model.

---

CORE PRODUCT CONCEPT

The application should have a central concept:

One Shape → Many Web Representations

Internally maintain a normalized vector representation of the shape.

From that representation generate:

1. SVG
2. SVG path
3. CSS polygon
4. CSS path
5. CSS clip-path
6. HTML/CSS
7. React JSX
8. JSON

The user should never need to recreate the shape separately for each output.

For example:

PATH
↓

CSS clip-path polygon

or:

POLYGON
↓
Smooth Bézier conversion
↓
SVG path

# PATH → POLYGON

Provide a dedicated conversion tool.

When converting a path into a polygon:

1. Sample the Bézier curves
2. Generate points along the curve
3. Simplify the points
4. Preserve the visual shape as accurately as possible
5. Generate normalized percentage coordinates
6. Output CSS polygon

Example:

clip-path: polygon(
  0% 50%,
  10% 20%,
  30% 5%,
  50% 0%,
  70% 5%,
  90% 20%,
  100% 50%,
  90% 80%,
  70% 95%,
  50% 100%,
  30% 95%,
  10% 80%
);

Provide controls:

- point count
- tolerance
- simplification
- percentage/pixel output

# PERFORMANCE

The application should feel immediate.

Avoid unnecessary React re-renders.

Use memoization where useful.

Keep geometry calculations outside React rendering when possible.

For complex paths, update only the necessary SVG elements.

- path simplification
- polygon conversion
- boolean operations
